- **v1.24–v1.28（2026-10-29，已同步线上）**：做过一轮数据备份与版本形态的探索，最终收敛为「一个链接、一套代码、数据以本机为主」；公开版只保留纯本地能力，相关实现细节未收录。

- **v1.23（2026-10-29，修复「手机端一直加载打不开」与「桌面图标不更新」，已同步线上）**：根因是 v1.19 为提速把 SW 导航改成 **cache-first**——缓存里的旧 `index.html` 会长期钉住，一旦它引用的 hash 资源被新版本替换（或缓存被系统清理），就会白屏、启动占位一直转；同理桌面图标永远走缓存，看不到新版本。修复：① 导航改为 **网络优先 + 1 秒 head start**（1 秒内拿到新 HTML 就直接用，超时/离线立刻用缓存渲染，结果在后台刷新缓存），发版即生效、弱网也不卡；② `CACHE` 升 **v5**，activate 时删除全部旧缓存（坏缓存随版本消失）；③ 注册加 `updateViaCache: 'none'`，并在回到前台时 `reg.update()`；④ 启动占位内置**加载失败自救面板**（6 秒未挂载 → 显示「重新加载 / 清除缓存后重载」，后者会 unregister SW + 清空 CacheStorage）；⑤ 数据读取超过 6 秒时，习惯页显示「重新加载」入口。

- **v1.22（2026-10-29，iOS 体感授权 · 页脚文案 · 震动诊断，已同步线上）**：① **iOS 体感每次都失效的根因定位**——苹果不允许网页持久授权，`DeviceOrientationEvent.requestPermission()` **每个页面会话都必须重新调一次**，且必须在用户手势内；原实现挂在 `pointerdown`（Safari 对该事件的「用户激活」判定不稳）→ 改为 `touchend / click / pointerup` 三重兜底，打开后任意点一下就自动弹授权；新增 `motionState`（unknown/granted/denied/unsupported）与 `motionSeen`（是否真的收到非零方向数据），设置页按状态给出不同说明，不再让用户猜；② 设置页底部三行说明删除，其中「严格当日记录…」改为**「往之不谏，来者可追，求因不求果」**放到习惯页最下方（右侧留出加号位置）；③ **震动**：`vibrate()` 改为同步触发（`await` 之后发会被部分实现忽略）、气泡/坏习惯点击都短震 10ms、设置里打开时试震一次；**iPhone / Safari 没有 Vibration API（系统限制，无法修复）**，无此能力时开关自动置灰并说明，Android 正常可用。

- **v1.21（2026-10-28，小恶魔重绘 · 暗影区列表 · 暂停口径重做，已同步线上）**：① **小恶魔按 😈 参考重绘**——红色圆头 + 白角 + 绿眼 + 咧嘴露牙；**今天记录过 → 睁眼坏笑**（图标位转暗红发光、露小尖牙），**未记录 → 闭眼打盹**且红色褪暗，连续未发生越久越淡越小（不再是无害的灰团子，但也不吓人）；② **列表暗影区改为与好习惯完全一致的行结构**（38px 图标位 / 名称 + 连续天数 / 本周点阵 / 记录圆点），去掉整块深色底；左滑「归档 / 删除」不再被卡片盖住（复用同一套 `row-wrap` 结构）；③ **暂停口径重做**：`Habit.suspensions` 记录暂停区间——**暂停当天仍算活跃**（当天已完成的保留、月历仍显示完成、仍计入期望），**次日起**才排出期望；统计页**包含已暂停习惯**，所以「暂停」不会让任何历史数字变小，只是不再增长；**恢复后从恢复当天重新计入**（当天即可记录）；周点阵把暂停区间画成灰点（不适用），不再误显示为「未完成」。

## 1. 项目概述



### 1.1 背景与问题



用户近期想要养成多个日常习惯（早起、冥想、跑步、读书等），同时想改掉少数坏习惯（熬夜、刷手机等），现状是：



- 缺少一个**低成本的每日打卡入口**——打开、点击、完成，最好 3 秒内搞定；

- 更缺少**长期、可视化的进度反馈**——坚持的动力很大程度上来自"看见自己的积累"；

- 市面上的工具两极分化：一类极简但枯燥（纯列表），一类有趣但复杂沉重（RPG 游戏化），且数据可视化普遍不够好用；

- 录入体验差：大多数 App 一上来就让用户填表，而用户要的是**"做选择，而不是做输入"**。



### 1.2 产品定位



> 一个「本地优先、苹果式极简、有点好玩」的个人习惯追踪工具：好习惯用气泡戳破，坏习惯用暗影诚实记录，每次坚持都可能掉落小惊喜。



差异化四点：



1. **形式可切换的打卡交互**——默认「气泡戳破」，可切换极简列表等形式，解决"用久了无聊"的问题；

2. **数据可视化是核心卖点而非附属功能**——双向竖状图（上好习惯/下坏习惯）、圆圈月历（绿=完成/红=未完成）、年度热力图一应俱全；

3. **选择式录入 + 双模式**——创建习惯全程点选；同时支持好习惯（养成）与坏习惯（诚实记录）两种模式；

4. **严格当日记录 + 掉落收集**——不补签、不算账，记录诚实；完成时的随机掉落与收藏提供纯粹的正反馈。



### 1.3 产品目标



- 一次打卡操作 ≤ 3 秒，从打开到完成 ≤ 2 次点击；

- 可视化数据覆盖：日 / 周 / 月 / 年四个时间粒度，单习惯与全局两个视角；

- 数据 100% 存储在本地，隐私零上传，支持随时导出；

- 添加习惯全程无需打字（选择式流程），但任何属性均可后续编辑；

- 支持 1–3 个坏习惯的诚实记录，与好习惯共享同一套可视化语言。



### 1.4 目标用户



**核心画像**：自我提升型个人用户，25–40 岁，同时培养最多 6 个好习惯、想改掉 1–3 个坏习惯，重视数据反馈，审美偏好苹果系极简风格，手机是主要使用设备。



**次要画像**：桌面端用户（办公室场景，屏幕大，气泡画布体验更爽）。



### 1.5 设计原则



1. **一屏一动作**：打卡屏只做打卡，数据屏只看数据；

2. **选择优于输入**：能点选的不让打字；

3. **反馈要爽**：动画、音效、震动、掉落四件套，完成瞬间要有" celebration（庆祝感）"；

4. **数据自己会说话**：所有统计图形化，不堆数字报表；

5. **本地优先、隐私优先**：无账号、无服务器、无社交；

6. **当日事当日毕**：严格当日记录——不补签、不冻结、不修复；错过就错过，第二天是新的一天，记录必须诚实；

7. **诚实优先于道德**：只记录真实发生的事——没发生就无需记录，发生了就诚实点击；产品不做说教、不做羞辱、不制造亏欠感；

8. **克制数量**：好习惯同时最多 6 个——习惯养成重在逐个击破，少才能盯得过来，画面也排得开；

9. **惊喜而非压力**：掉落收集、次日庆祝提供正反馈。



### 1.6 平台策略与路线（已确认）



| 方案 | 优势 | 劣势 / 成本 | 结论 |

| --- | --- | --- | --- |

| **Web（PWA）** | 全部能力已按此设计：IndexedDB、体感、WebAudio、SVG 可视化、PWA 添加到主屏即"应用化"；一份代码多端运行；零审核、即时上线、随时更新 | iOS Safari 个别限制（体感需授权、存储可能被清理）；国内安卓浏览器 PWA 体验参差 | **本期主战场** |

| **GitHub 可下载应用** | 桌面完整体验、真文件存储、无浏览器怪癖、可版本化管理 | 需要打包分发；与"手机端随手打卡"的主场景不完全重合 | **后续低成本加**：用 Tauri 把同一份 Web 代码打成桌面安装包，挂 GitHub Releases + Pages 托管，核心代码 100% 复用 |

| **微信小程序** | 无需安装、微信内可达、订阅消息提醒 | 需重写存储层（wx storage，无 IndexedDB）与渲染适配（Canvas/Skyline），个人主体有类目限制，上线需审核；本产品无社交需求，小程序的分发优势用不上 | **本期不做**；核心逻辑是纯 TypeScript，未来如出现"分发/提醒"强需求可移植评估 |

| **支付宝小程序** | — | 生态对个人工具类产品最弱，无额外优势 | **不做** |



**已确认路线**：Web/PWA 先行并发布在线链接 → 手机"添加到主屏"解决移动端 → 需要"可下载"时用 Tauri 出桌面版挂 GitHub → 小程序仅当未来出现强需求时作为独立移植项目评估。三个形态长期可以共存，因为数据模型、位图统计等核心逻辑都是平台无关的纯 TypeScript，差异只在存储与渲染外壳。

## 2. 调研结论



### 2.1 竞品分析



| 产品 | 核心形式 | 优势 | 不足 / 我们的机会 |

| --- | --- | --- | --- |

| **Streaks**（iOS，Apple Design Award） | 任务圆环 + 极简列表 | 苹果级打磨、Watch/小组件 | 仅苹果生态、形式传统、买断制 |

| **HabitKit** | 年度热力图（GitHub 风 tile grid） | "一眼看一年"的标杆可视化；三步创建；离线无账号 | 交互形式单一（点击格子）；统计为付费点 |

| **Way of Life** | 绿/红日历 + 图表 | 与用户需求高度一致的绿/红日历语义 | 无游戏化、界面老旧 |

| **WaterDo**（Forest 团队） | 任务变水球，**点击戳破** | 验证了"气泡戳破"的爽感；每日回顾 | 偏玩具，数据可视化弱 |

| **HabitBubbles**（iOS） | 习惯变气泡，随连续天数长大 | 气泡 + streak 成长的组合很有启发 | 无日历/曲线等深度可视化 |

| **PopHabit** | 一键 pop 动画 + 音效 | ADHD 友好：重完成率、轻 streak、零羞辱 | 功能单一 |

| **Habitica** | RPG 游戏化（升级/掉血/社交） | 游戏化深度标杆 | 太重太吵，与"极简"相悖 |

| **Daychain** | 链条可视化 + 宽容机制（护盾/休假模式） | "不断链"隐喻 + 断签保护的理念先进 | 仅 iOS |

| **Loop**（Android，开源） | 极简 + 强统计 | 统计维度全、隐私好 | 平台受限 |



### 2.2 关键洞察（来自调研）



1. **"气泡戳破"是被多产品验证过的爽感交互**（WaterDo 的水球、HabitBubbles 的气泡、PopHabit 的 pop 动画），且 PopHabit 的"一键 pop + 满足感动画"直接命中"低摩擦打卡"；

2. **GitHub 风年度热力图是习惯可视化的通用语言**（HabitKit 的核心卖点），用户几乎零学习成本；

3. **关于补签与宽容机制**：调研发现补签/护盾类宽容设计（Daychain 的 shields、init.Habits 的 freeze）能缓解断签挫败，但本产品**明确不采用**——产品哲学是「严格当日记录」：当天没做就是没做，不补签、不冻结、不修复，过去日期只读。断签的负面情绪由产品设计本身规避：以**完成率**为主指标（而非 streak 数字），正反馈交由**掉落收集**和**次日庆祝**承担，不做任何负反馈机制；

4. **坏习惯的记录模型是"账本"而非"战场"**：用户明确——没做坏事的那天**没有什么可记录的，所以不需要点击**；做了才诚实点击。这不是"忍住/抵抗"的意志力叙事，而是中性的事件记录（和记账一样：没花钱就不用记，花了才记）。界面文案与状态机全部按此语义设计；

5. **本地优先 + 无账号是趋势**：HabitKit、Loop、init.Habits 均强调离线、隐私、免登录，与个人习惯工具的性质吻合；

6. **录入摩擦是留存杀手**：HabitKit 的"名字 + 颜色，没有别的要填"被反复好评——这就是"选择优于输入"的业界验证；

7. **省内存存储有标准答案**：每个习惯一年的打卡记录压缩为位图（Bitmap）仅需 **46 字节**（365 bit），查询和统计全部 O(1) 位运算（详见第 8 章）。



### 2.3 对本产品的启示



- 交互形式：以「气泡戳破」为默认主打，用「极简列表」兜底效率场景，做成**可切换的形式系统**；

- 可视化：全局看板（每日完成数曲线 + 年度热力图）+ 单习惯日历（绿/红）+ 周曲线，全部自绘以保证苹果级质感；

- 指标策略：今日完成率环为主角，streak 作为辅助徽章；**不提供补签**，用完成率代替惩罚；

- 录入：模板点选两步流，默认模板覆盖高频习惯（早起/冥想/跑步/读书/熬夜/刷手机……）；

- 惊喜层：每次完成掉落小物件 + 收藏，把"坚持"变成"寻宝"，这是与所有竞品都不同的记忆点；

- **参考「习惯点点」（habitdots.com，上海仙蒂网络，iOS/Android）的调研结论（v1.4 深化）**：**借鉴**——习惯行的 7 日小圆点阵、统计页整体布局（顶部数字行 / 双向竖状图 / 打卡频次分布 / 全部习惯列表 / 习惯详情页的月历 + 年度点阵）、极简的今日页；**不借鉴**——能量/奖励兑换闭环（我们用掉落收藏，更轻）、Pro 付费与订阅、分享图与社群（无社交）、难度/周期/频数等复杂设置（保持极简）。

## 3. 产品范围



### 3.1 本期范围（MVP）



1. 习惯管理：创建（选择式，好/坏两种类型）、编辑、归档、删除、排序；好习惯活跃上限 **6** 个；

2. 每日打卡：「今天」页，气泡 / 列表两种形式；**仅当天可操作，过去日期只读**；

3. 掉落物与收藏：完成好习惯随机掉落小物件（重力物理 + 体感/拖拽互动），收藏槽与收藏室；

4. 坏习惯模块：1–3 个坏习惯，暗影区丑萌小恶魔形式，同屏分区；**未发生 = 无需记录，发生 = 点击记录一次（当天二值，多次不管）**；次日庆祝/提示条；

5. 数据可视化：「数据」页——今日完成率、双向竖状图（30 日）、圆圈月历（绿=完成/红=未完成）、年度热力图、统计卡片、范围切换器（全部 / 单习惯）；

6. 设置：主题（浅/深/跟随系统）、周起始日、打卡形式、音效、震动、体感、掉落动画、暗影区折叠、数据导出（JSON/CSV）、清空数据；

7. PWA：可添加到手机主屏，离线可用；

8. 首次引导：音效/震动/体感默认开启，首次使用一句话提示。



### 3.2 本期不做



- 补签、 streak 冻结/护盾、补签卡等一切"修复过去"的机制（产品哲学明确排除）；

- 每周 N 次目标（已确认不做）；

- 账号系统、云同步、多设备同步（后续迭代）；

- 提醒推送（Web 通知能力后续接，见 3.3）；

- 社交、排行榜、分享卡片；

- 计时 / 计量类目标（如"冥想 20 分钟"的计时器，本期仅记录"完成/未完成"）；

- 付费与订阅；

- 微信 / 支付宝小程序（平台路线已确认，见 1.6）。



### 3.3 后续迭代方向（按优先级）



1. Tauri 桌面版打包，挂 GitHub Releases / Pages（见 1.6）；

2. 云同步与多端（账号 + 时间戳合并）；

4. 新打卡形式（活动圆环、鱼缸彩蛋等，形式插件化）；

## 5. 功能需求



### 5.1 习惯管理模块



#### 5.1.1 创建习惯（单屏，点模板即创建）



```

顶部切换：［好习惯 · 养成］ ［坏习惯 · 记录］



选模板（点一下即创建，图标颜色已预设）

  好习惯模板：早起 ☀️橙 / 冥想 🧘紫 / 跑步 🏃绿 / 读书 📖蓝 / 喝水 💧青 /

              早睡 🛏️靛 / 健身 🏋️粉 / 背单词 📝黄 / 写日记 / 学英语 /

              少看手机 / 吃早餐 …

  坏习惯模板：熬夜 🌙 / 刷手机 📱 / 拖延 ⏳ / 吃零食 🍪 / 抽烟 🚬 /

              喝奶茶 🧋 / 赖床 🛌 / 冲动消费 🛒 …



── 或者，自己定义一个（同屏下方，随时可跳过）──

  · 名称：输入框（自定义时唯一需要打字的地方）

  · 颜色：苹果系统色全色系（约 10 色，任选）

  · 图标：可选——不选就只有颜色

```



- 好习惯模板 12+、坏习惯模板 8+，可持续增补；**模板自带预设图标与颜色**，点一下直接创建；

- 自定义区在同屏下方，不与模板抢注意力；任何属性后续都可改；

- **不设分类**：习惯总数有限（好习惯 ≤6、坏习惯 1–3），分类是冗余层级。



#### 5.1.2 编辑 / 归档 / 删除 / 排序



- **编辑**：名称、颜色、图标均可改；历史数据不受影响；

- **归档**：从「今天」页消失，历史数据保留在「数据」页可查；可随时恢复；

- **删除**：二次确认，提示"历史记录将一并删除"，不可恢复；

- **排序**：长按拖拽调整顺序（M4 实现）；

- **归档 / 删除**：「今天」页**左滑习惯行**露出「归档 / 删除」；删除需二次确认；已归档的习惯在「设置」页可恢复或删除，历史数据保留；

- **数量上限**：好习惯活跃上限 **6 个（固定，不提供调节）**——习惯养成重在逐个击破，多了影响注意力与完成率，6 个也正好让气泡画面排得开；坏习惯 1–3 个。



#### 5.1.3 数据结构约束



- 习惯 ID：创建时生成的 UUID（不用自增，方便后续同步）；

- 习惯类型：`type: 'good' | 'bad'`，决定其出现在气泡区还是暗影区、交互方向与数据语义；

- 日期一律使用**本地日字符串 `YYYY-MM-DD`**（规避时区 bug，业界公认做法）。



### 5.2 每日打卡模块（Tab：今天）



#### 5.2.1 页面结构



```

│ 10月23日 周五              │  只有日期（完成率环已移除）

│ ┌─────────────────────────┐ │

│ └─────────────────────────┘ │

│      ○ 早起                 │

│   ○ 冥想        ○ 跑步       │  习惯列表（≤6 个好习惯）

│         ○ 读书      ★掉落中  │   行内 7 日点阵，无多余文字

│ ░░░░░░░ 暗影区 ░░░░░░░░░░░░ │

│  （熬夜·打盹）（刷手机·打盹） │  坏习惯：未发生 = 无需记录

│ ░░░░░░░░░░░░░░░░░░░░░░░░░░ │

│  ☆◇◈ 收藏槽 28  ›          │  掉落物沉淀处

└─────────────────────────────┘

```



- **仅显示今天**：不提供过去日期切换——过去只读（历史请在「数据」页查看），这是「严格当日记录」的界面体现；

- 空状态（0 习惯）：全屏引导「创建你的第一个习惯」+ 模板快捷入口；

- 次日庆祝条：今天首次打开时，若昨天所有坏习惯都未发生 → 绿色庆祝条「昨天零发生，暗影们睡得很沉」；若有发生 → 中性提示条「昨天发生，今天重新开始」。



#### 5.2.2 形式系统（好习惯专用）



打卡形式是一等公民，在设置中随时切换，默认「气泡」。



**形式 A：气泡画布（默认）**



- 每个好习惯是一个半透明气泡，在画布中**缓慢漂浮**（正弦上下漂 + 轻微左右摆 + 边界回弹，纯 CSS/JS 物理，性能优先）；

- 气泡内显示图标 + 名称；颜色 = 习惯色（苹果系统色）；

- 气泡大小带**成长激励**：连续天数越多，气泡略大略亮（+0 ~ 40%），新习惯/刚断签的稍小且透明度降低——借鉴 HabitBubbles 的成长隐喻，但不制造焦虑；

- 习惯上限 6 个，**均匀分布漂浮即可**，无需聚集逻辑；

- **点击 = 戳破**：气泡高亮闪白 → 碎裂为 8–12 个小粒子向外扩散 → **触发掉落（见 5.2.4）** → 气泡消失，移入底部「已完成」条；同时播放合成音效（"啵"）+ 10ms 震动（navigator.vibrate）；

- **取消完成**：点击底部「已完成」条中的习惯 → 确认后气泡回到画布（防误触；仅当天可取消）；

- **全部完成时**：全屏 confetti 粒子庆祝 + 文案「完美的一天」+ 必掉一个稀有以上物件。



**形式 B：极简列表**



- Apple Reminders 风：左图标 + 名称 + streak 小徽章，右侧圆形勾选；

- 点击勾选：圆圈填充 + 弹性缩放动画 + 音效 + 同样触发掉落；再点取消（无需确认）；

- 适合效率场景与无障碍兜底。



**形式 C（后续）：活动圆环**——Apple Watch 风三环，每个习惯一环。

**形式 D（后续彩蛋）：鱼缸**——打卡 = 投喂，习惯 = 小鱼，连续喂养鱼会长大。



#### 5.2.3 打卡写入逻辑（严格当日）



- 点击完成 → 写入 `checkins`（habitId + 今天日期）→ 同步置位年份位图 → UI 立即刷新（乐观更新）；

- 再次点击今天已完成的 → 删除记录 + 位图清零（**仅当天允许，防误触**）；

- **过去的日期一律只读**：不提供补签入口，UI 上不出现历史日期切换；写入层强制校验 `date === today`，非法写入直接拒绝——这是数据诚实性的核心承诺；

- 未完成 = 什么都不发生，当天结束时自然成为日历上的一个空格。



#### 5.2.4 掉落物系统



**触发规则**



| 事件 | 掉落 |

| --- | --- |

| 完成一个好习惯（戳破/勾选） | 随机 1 个：普通 70% / 稀有 25% / 史诗 5% |

| 完美一天（好习惯全部完成） | 必掉 1 个稀有以上 |

| 好习惯连续 7/14/21/30/40/50/60… 天 | 当次稀有概率**大幅提升（不保底）** |

| 坏习惯连续未发生 7/14/21/30/40/50/60… 天 | 同上 |

| 坏习惯发生（点击记录） | 不掉落——星光点名动画本身即反馈 |



> **v1.38 现行规则（用户真机反馈后调整；上表为 v1.0 原始设计留档）**：收藏品只在「完美一天」掉落。**达成完美一天不再提升稀有 / 史诗概率，只让普通收藏更容易出现**——普通日 N 70% / R 25% / SSR 5%；只有连续 7/14/21/30/40/50/60… 天的**阶段性里程碑日**，才把稀有与史诗提升到 R 55% / SSR 30%（N 15%）。概率均为「提升」而非「保底」，不承诺必得。



**物理规格**



- 抛出：从气泡中心以随机初速度向上抛出（水平 ±40px/s，向上 120–180px/s）；

- 重力：约 1400 px/s²（按屏幕观感标定）；

- 弹跳：落到屏幕下沿时恢复系数 0.45，弹跳 2–3 次后静止；

- 体感：监听 `deviceorientation` 的 gamma 值（左右倾斜），转化为水平加速度 ±600 px/s²，物件会朝倾斜方向滚动滑动（iOS 需用户手势授权，设置内提供「开启体感」按钮）；

- **桌面端**：鼠标可**按住拖拽**物件，松手时按拖拽速度**抛出**（惯性 + 重力 + 弹跳），触屏设备拖拽即原生支持；

- 性能：同屏物理物件上限 6 个，超出的直接沉入收藏槽；

- 无障碍：`prefers-reduced-motion` 时跳过物理，直接淡入收藏槽。



**小物件库（数据驱动，可持续扩充）**



| 稀有度 | 物件 |

| --- | --- |

| 普通 | 星星、糖果、樱花、泡泡、棉花糖、饭团 |

| 稀有 | 四叶草、纸飞机、小蛋糕、月亮、风车 |

| 史诗 | 金色小鱼、彩虹、流星 |



- 物件定义在数据文件中，后续版本可**新增物件与节日限定**（樱花季、雪花、灯笼……），无需改逻辑；

- 收藏槽：「今天」页底部半透明长槽，展示最近掉落的最多 8 个，点击展开收藏室；

- 收藏室（全屏页）：网格展示已收集物件（图标 + 名称 + 稀有度 + 数量 + 首次获得日期）；未收集的显示剪影与"未发现"，制造收集欲；

- 统计：总收集数、各稀有度数量；

- 音效：普通"叮"、稀有双音、史诗小旋律（WebAudio 合成，零资源文件）；

- 设置内可关闭掉落动画（仍计入收藏）。

| 双向竖状图 | 近 30 天，**零线**向上/向下 | 按当前筛选显示单侧：好习惯 = 每日完成数（绿，向上）；坏习惯 = 每日发生数（红，向下）；左侧整数刻度（1 个 = 1 格） | 点击柱子看当日明细 |

| 全部习惯 | 习惯卡片列表 | 每个习惯：图标 / 名称 / 创建日期 / 完成次数 / 连续 / 完成率（坏习惯：发生次数 / 连续未发生 / 未发生率） | 点击进入习惯详情页（5.3.5） |



- 色彩语义：**好习惯 = 绿、坏习惯 = 红**（v1.5 确立）——完成/未发生用苹果绿 #34C759 系，发生/未完成用红 #FF6961 系（月历用淡红 #FCEBEB + 深红字 #D70015）；创建前/未来 = 灰；坏习惯没做 = 灰（不用绿）；

- 统计页已**无**「今日完成率」卡片与底部四张统计卡（v1.4 移除，由顶部数字行 + 全部习惯列表取代）；

- 所有图表自绘 SVG（不用图表库默认皮肤），保证苹果级质感与完全的主题一致性。



#### 5.3.4 统计口径定义



- **完成次数**：完成了多少个习惯（人次），与「打卡天数」（至少有一个完成的天数）区分开；

- **连续天数（streak）**：好习惯=连续完成天数；坏习惯=连续未发生天数；从今天（若今天未完成/已发生则从昨天）向前数，且不早于创建日；读时从位图实时计算，不存储；

- **完成率 / 未发生率**：完成（未发生）次数 ÷ 创建至今的天数；

- **发生**：当天点击过即算发生，二值记录，当天多次不管。



#### 5.3.5 习惯详情页（v1.4 新增）



- 入口：统计页「全部习惯」列表点击任一习惯（全屏子页，左上角返回）；

- 内容：习惯头图（图标 + 名称 + 创建日期）+ 三项数字（完成/连续/完成率）+ **圆圈月历** + **年度点阵**；

- 色彩原则（v1.5）：好习惯详情 = 绿色系（月历绿=完成、红=未完成、灰=未开始/未来，今日深绿描边）；坏习惯详情 = 红色系（图标红、月历**发生=红、没做=灰**，今日深红描边）；

- 年度点阵图例 = 「**做了 / 没做**」二值（好习惯：绿点 = 做了；坏习惯：红点 = 做了；灰 = 没做），"很简约，完成了就是一个点"；

- 月历可翻月，过去只读。



### 5.4 坏习惯模块



#### 5.4.1 形式：暗影区 · 丑萌小恶魔



每个坏习惯是住在「今天」页底部**暗影区**的一只丑萌小生物（灰色调、耷拉耳、蜷缩打盹的样子），与气泡形成刻意反差：



| 维度 | 好习惯（气泡） | 坏习惯（暗影） |

| --- | --- | --- |

| 位置 | 画布上半部，漂浮 | 屏幕底部暗影区，静止蜷缩 |

| 色彩 | 习惯色（苹果系统色），明亮 | 灰调，暗影区深色底 |

| 交互 | 做了 → 点击完成 | 未发生 → **无需记录**；发生 → **点击记录一次** |

| 反馈 | 戳破 + 掉落 | 星光点名（当天仅一次） |

| 体型语义 | 连续越久越大 | 连续未发生越久越小越浅（越虚弱） |

| 数据语义 | 越多越好 | 越少越好 |



**核心语义**：这不是"忍住/抵抗"的意志力叙事，而是**中性的账本**——没做坏事的那天没有什么可记录的，所以不需要点击；做了才诚实点击记一笔。就像记账：没花钱就不用记，花了才记。**当天发生多次不计数，发生过就行**（再点仅提示"已记录"）。



**状态机**：



```

未发生（打盹）

   │ 今天发生了 → 点击

   ▼

已记录（当天锁定；再点仅 toast「已记录」）

   │

   ▼

新的一天 → 回到未发生

   （体型由连续未发生天数决定：0 天 = 基准，

     连续 7/14/21/30/40/50/60 天逐级缩到最小）

```



**星光点名动画**：点击后小恶魔头顶弹出「已记录」+ 几颗金色星光绕身一圈。**无红色警告、无失败提示、无扣分、不说教**——点了就是诚实的表现，产品只负责把账记下。



**次日庆祝/提示条**（今天首次打开时出现）：

- 昨天全部未发生 → 绿色庆祝条「昨天零发生，暗影们睡得很沉」+ 小恶魔集体打盹动画；

- 昨天有发生 → 中性提示条「昨天发生，今天重新开始」。



**里程碑**：连续未发生 7/14/21/30/40/50/60 天，小恶魔逐级缩到最小，且当日起稀有掉落概率提升（不保底）。



**备选形式**（已评估，未采用）：乌云（点击后下雨放晴，意象略丧）、污点（点击擦拭，交互单一）。暗影小恶魔胜出原因：丑萌有记忆点，"打盹/缩水"天然表达"被冷落而虚弱"，且与气泡的明暗对比构成产品独特的视觉语言。



#### 5.4.2 布局：同屏分区



- 暗影区位于「今天」页底部，一条深色内嵌圆角带（浅色主题 `#1C1C1E` / 深色主题 `#2C2C2E`），与明亮气泡区形成刻意的明暗对比，本身就是情绪隔离；

- 1–3 只小恶魔横向排列，不拥挤；

- 可在设置中折叠暗影区（默认展开）；

- 评估过的分屏方案（独立 Tab）未采用：坏习惯的数据完整性恰恰依赖用户主动点击，分两个入口会显著增加"忘记记录"的概率。



#### 5.4.3 数据可视化



与好习惯完全一致的语言（见 5.3），语义方向相反（见 5.3.2 / 5.3.3 / 5.3.4）。用户自己会理解"它越趋于 0 是越好的"——产品不额外说教。

## 7. 交互与视觉规范（Apple-like 极简）



### 7.1 版式与字体



- 字体栈：`-apple-system, BlinkMacSystemFont, "SF Pro Text", "PingFang SC", "Helvetica Neue", sans-serif`；

- 字号层级：页面标题 28/600（iOS Large Title 风）、区块标题 17/600、正文 15/400、辅助 13/400；

- 数字与统计：等宽或 SF Mono 风，保证图表对齐；

- 布局：手机优先（≤ 430px 宽流式），桌面端居中限宽 480–720px，气泡画布在桌面可扩展至全高；

- 留白：区块间距 ≥ 24px，卡片内边距 16–20px，一屏一个视觉焦点。



### 7.2 色彩



**习惯色（苹果 iOS 系统色，用户任选）**



| 名称 | 色值 | 名称 | 色值 |

| --- | --- | --- | --- |

| 红 | `#FF3B30` | 紫 | `#AF52DE` |

**语义色（与习惯色同源，统一苹果系统色）**

- 未完成 / 发生（负向）：`#FF3B30`（系统红；默认以淡红填充 + 系统红描边呈现，不刺眼）

- 主文字：浅色 `#1D1D1F` / 深色 `#F5F5F7`；

- 图表色：全局视图用蓝色单色系；色阶统一 5 档。

- 圆角：卡片 16–20px、气泡全圆、按钮全圆、Sheet 顶部 24px、暗影区内嵌圆角 14px；

- 描边：0.5px 发丝线（`rgba(0,0,0,0.08)`）；

- 阴影：克制使用，仅悬浮按钮与 Sheet 有大而散的轻阴影。



### 7.4 动效（"不要太糙"的关键）



- 曲线：弹性 spring `cubic-bezier(0.34, 1.56, 0.64, 1)`，时长 200–400ms；

- 戳破粒子：8–12 个 4–8px 圆点，向外扩散 + 淡出，总时长 ~500ms；

- 掉落物理：见 5.2.4（重力、弹跳、体感、拖拽抛出）；

- 星光点名：点击小恶魔后「已记录」弹出 + 3–4 颗金星绕身一圈，~600ms；

- confetti：全屏 60–100 个彩色纸片，重力 + 旋转，~1.5s；

- 所有动效尊重 `prefers-reduced-motion`；

- 目标：交互响应 < 100ms，动画 60fps。

## 8. 数据模型与存储设计（省内存方案）



### 8.1 实体模型



```

habits（习惯定义）

  id           string   UUID

  type         string   'good' | 'bad'

  name         string   名称

  icon         string   图标标识

  color        string   苹果系统色标识

  createdAt    string   ISO 时间

  archivedAt   string?  归档时间

  sortOrder    number   排序



checkins（好习惯打卡事件，稀疏存储——只记"完成"）

  habitId      string

  date         string   'YYYY-MM-DD'（本地日，仅当天可写入）

  主键: [habitId + date]



occurrences（坏习惯发生记录，稀疏存储——只记"发生了"，二值）

  habitId      string

  date         string   'YYYY-MM-DD'（仅当天可写入，每天最多一条）

  主键: [habitId + date]



drops（掉落记录）

  id           string   UUID

  itemId       string   物件标识（数据驱动）

  rarity       string   'N' | 'R' | 'SSR'

  source       string   'pop' | 'perfect' | 'milestone'

  habitId      string?  关联习惯（里程碑来源）

  date         string   'YYYY-MM-DD'



items（掉落物件定义，数据驱动，后续可扩充）

  id           string

  name         string

  rarity       string   'N' | 'R' | 'SSR'

  limited      string?  节日限定标识（如 'sakura'）



settings（本地设置）

  key/value 结构，见 5.5

```



### 8.2 位图压缩（核心省内存设计）



每个习惯每一年的记录压缩为一个**年份位图**：



- 好习惯：位图第 `dayOfYear` 位 = 1 表示当天完成；坏习惯：= 1 表示当天发生；

- 一年 365 位 = **46 字节**（闰年 366 位同样容纳）；

- 操作：记录 `SETBIT` O(1)；查询 `GETBIT` O(1)；月统计 `POPCNT` O(1)；连续天数从今天位向前扫描；

- 存储容量对比：



| 方案 | 1 个习惯 1 年 | 10 个习惯 10 年 | 单日查询 | 月度统计 |

| --- | --- | --- | --- | --- |

| 全量日状态 JSON | ~1–2 KB | ~1–2 MB | O(1) 索引 | 遍历 30 项 |

| 稀疏事件记录 | ~10–30 KB | ~1–3 MB | 索引查找 | 范围扫描 |

| **年份位图** | **46 B** | **4.6 KB** | **O(1) 位运算** | **popcount O(1)** |



### 8.3 混合架构



- **IndexedDB 事件表（checkins / occurrences）为唯一事实源（source of truth）**，保证可导出、可审计、可恢复；

- **年份位图为读缓存**：启动时懒加载当前年份位图，查询/统计全部走位图；跨年时按需加载；

- 写入 = 事件表写入 + 位图同步置位；位图可由事件表随时重建；

- 严格当日约束在写入层强制：`date !== today` 的写入一律拒绝；坏习惯同日重复写入直接忽略（二值语义）——这是数据诚实性的技术保障；

- 容量估算：即使 9 个习惯 × 10 年，事实源事件记录也就 ~3 MB 量级，浏览器存储绰绰有余。



### 8.4 技术选型说明



- **IndexedDB（Dexie.js 封装）**：浏览器原生、离线、无后端、GB 级容量；

- 不选 localStorage：Safari 隐私模式会抛 QuotaExceededError，且无索引查询能力；

- 不选服务端数据库：违背"本地优先、隐私优先"原则；后续云同步再议。

## 10. 非功能需求



1. **离线可用**：断网/飞行模式下全部功能可用（PWA）；

2. **隐私**：数据 100% 本地，无任何网络上传，无统计 SDK；

3. **数据诚实性**：过去日期只读，写入层强制校验当天；坏习惯同日二值；

4. **响应式**：手机优先；桌面自适应（画布扩大、信息密度略升）；

5. **兼容**：Chrome / Safari / Edge 最新两个大版本；iOS Safari 16+；

6. **无障碍**：支持 `prefers-reduced-motion`；列表形式可完全键盘操作；对比度满足 WCAG AA；体感关闭时全部功能可用；

7. **数据安全**：导出即所得；清空数据需二次确认并提示不可恢复；

8. **可维护**：业务逻辑（连续天数/位图/统计/物理）写成纯函数并附单元测试；核心逻辑平台无关（纯 TypeScript），为未来桌面版/移植留可能。
